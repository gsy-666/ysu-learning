# 第04讲：递归算法，从零学到会做题

依据：递归课件（原始文件未收录）第4—6页，教材第3章。先理解“调用自己时发生什么”，再学阶乘、汉诺塔、Fibonacci和课件中的恰好装满问题。本文示例除说明外均为教学自编。

## 1. 先把过程当成一个小计算器

过程接收输入、执行步骤，并把结果交给调用者。例如FACT(3)表示让FACT计算输入3对应的结果。过程里写return(6)，调用者就拿到6，这次调用结束。

一个过程允许调用其他过程，也允许调用自己。直接或通过其他过程间接调用自身，就是递归。递归的关键是把任务交给更小规模的同类问题，而不是毫无变化地重复原任务。

读递归代码前先问：输入是什么意思；返回什么；哪些输入可以直接回答；其他输入会调用什么更小问题。

## 2. 从数学意义理解阶乘

n的阶乘写作n!。当n≥1时，它是从n一直乘到1：3!=3×2×1=6，4!=4×3×2×1=24。数学上规定0!=1。

观察4!：它等于4×3!。因此，若已经能计算3!，再乘4就能计算4!。递归关系为：

```text
F(0)=1
F(n)=n×F(n−1)，n≥1
```

这里F(n)表示答案的数值。稍后分析耗时用T(n)，两者不要混淆。

### 2.1 完整SPARKS代码

```text
procedure FACT(n)
    //输入：非负整数n；返回：n!//
    if n = 0 then
        return(1)
    endif
    return(n*FACT(n-1))
end FACT
```

逐句解释：procedure定义过程；n=0时直接给出1；其他情况先计算FACT(n−1)，得到返回值，再乘以本层的n，最后把乘积返回。

return(n*FACT(n−1))不是先把一个未算完的式子交出去。右边表达式需要先求出数值，所以本层必须等待下一层调用完成。

### 2.2 向下调用：各层都暂时等待

调用FACT(3)时：

| 当前调用 | 需要做什么 | 当前状态 |
|---|---|---|
| FACT(3) | 3×FACT(2) | 等FACT(2)的答案 |
| FACT(2) | 2×FACT(1) | 等FACT(1)的答案 |
| FACT(1) | 1×FACT(0) | 等FACT(0)的答案 |
| FACT(0) | 直接返回1 | 到达出口 |

每次调用有自己的一份n。外层的n=3仍保留，下一层有自己的n=2。计算机用调用栈保存各层参数、局部状态和返回后继续执行的位置。

栈是后进先出：FACT(0)最后进入，最先完成；它完成后，才轮到等待它的FACT(1)。

### 2.3 向上返回：逐层完成等待的乘法

| 完成的调用 | 本层计算 | 返回值 |
|---|---|---:|
| FACT(0) | 使用出口 | 1 |
| FACT(1) | 1×1 | 1 |
| FACT(2) | 2×1 | 2 |
| FACT(3) | 3×2 | 6 |

递归题手算时，分开写调用顺序和返回顺序，通常比把所有变化挤在一起更容易检查。

## 3. 递归必须写清三件事

| 要素 | 含义 | 阶乘例子 |
|---|---|---|
| 出口 | 哪些情况不需要继续调用 | n=0时答案1 |
| 规模缩小 | 怎样把任务交给更小问题 | n变为n−1 |
| 利用返回值 | 小问题答案如何变成原答案 | 再乘本层的n |

还要说明合法输入。这里n是非负整数，因此反复减1会到0；若输入−3，单凭n=0出口不能保证终止。

常见错误：删掉出口会继续进入负数；写FACT(n)导致规模不变；只写FACT(n−1)而没有乘n，无法得到阶乘；把0!误设为0，也会让乘积错误。

## 4. 阶乘的时间、空间与循环版本

### 4.1 答案递推不等于耗时递推

答案的递推是F(n)=nF(n−1)，但并不是调用了n次FACT(n−1)：它只调用一次，然后做一次乘法。因此耗时递推为：

```text
T(n)=T(n−1)+Θ(1)
```

从n调用到0，共n+1次调用，每次固定数量的基本操作，时间Θ(n)。结果n!非常大，不代表执行了n!次操作。本章按基本算术为常数成本分析。

最深同时存在n+1层调用，每层保存固定数量的状态，因此辅助空间Θ(n)。空间看的是同时占用多少，不是把所有先后用过的存储累计相加。

### 4.2 循环版本

```text
procedure FACT_ITER(n)
    //输入：非负整数n；返回：n!//
    integer i
    result ← 1
    for i ← 1 to n do
        result ← result*i
    repeat
    return(result)
end FACT_ITER
```

n=3时result依次为1、2、6。n=0时循环体0次，直接返回初值1。时间仍为Θ(n)，额外只用固定变量，所以辅助空间Θ(1)。

递归与循环各有表达方式。简单递推常可改循环；一般递归转非递归需要用显式栈保存尚未完成的任务和执行位置，不能把所有递归都直接删掉调用改成一个for。

## 5. 汉诺塔：先理解三个柱子的任务

有A、B、C三根柱子，A上有n个盘子，小盘在大盘上。目标是把全部盘子从A移到C，B作辅助。规则：一次只移一个顶部盘子，任何时候大盘不能放在小盘上。

n=1时，直接A→C。n=2时，先小盘A→B，再大盘A→C，最后小盘B→C，共3次。

### 5.1 为什么分成三步

要移动最大的第n号盘，必须先移开它上面的n−1个盘。于是：

1. 把上面n−1个盘从来源柱移到辅助柱。
2. 把最大的盘从来源柱移到目标柱。
3. 把辅助柱上的n−1个盘移到目标柱。

第一步和第三步仍是汉诺塔，只是盘子更少、柱子的角色改变。注意“辅助柱”是当前调用的角色，并不永远叫B。

### 5.2 代码与参数顺序

```text
procedure HANOI(n,source,spare,target)
    //n≥0；source来源柱，spare辅助柱，target目标柱//
    if n = 0 then return endif
    call HANOI(n-1,source,target,spare)
    print(n,source,target)
    call HANOI(n-1,spare,source,target)
end HANOI
```

第一处递归要把上面的小盘移到spare，因此原target临时充当辅助柱；第二处递归把小盘从spare移到target，原source临时充当辅助柱。print记录移动第n号盘的来源与目标。

调用HANOI(3,A,B,C)得到：

| 次数 | 移动 |
|---|---|
| 1 | 1号盘A→C |
| 2 | 2号盘A→B |
| 3 | 1号盘C→B |
| 4 | 3号盘A→C |
| 5 | 1号盘B→A |
| 6 | 2号盘B→C |
| 7 | 1号盘A→C |

### 5.3 复杂度为什么是指数级

设移动次数为M(n)，则M(0)=0，M(n)=2M(n−1)+1。每多一个盘，原来的移动工作做两遍，再增加中间那一次。

展开：M(n)=2[2M(n−2)+1]+1=4M(n−2)+3。继续得到M(n)=2ⁿM(0)+(2ⁿ−1)=2ⁿ−1。

因此时间Θ(2ⁿ)。但最深调用只有n+1层，辅助栈空间Θ(n)。先完成左边递归再进行右边递归，不能把所有递归调用数误当成同时存在的栈深度。

## 6. Fibonacci：看见重复计算

定义F(0)=0、F(1)=1、F(n)=F(n−1)+F(n−2)。前几项为0、1、1、2、3、5、8。

```text
procedure FIB(n)
    //输入：非负整数n；返回：第n项//
    if n ≤ 1 then return(n) endif
    return(FIB(n-1)+FIB(n-2))
end FIB
```

计算FIB(5)时要算FIB(4)和FIB(3)；而FIB(4)内部又要算FIB(3)和FIB(2)。同一个FIB(3)会被从头算两次，更小的状态还会重复更多次。

耗时关系T(n)=T(n−1)+T(n−2)+Θ(1)，为指数级。常用宽松上界O(2ⁿ)，紧确指数底数可写φ=(1+√5)/2，时间Θ(φⁿ)；初轮先掌握重复分支造成指数增长。

最深调用链每次至少减1，所以栈空间Θ(n)。两处递归先后求值，不是把两条完整调用栈一直同时保留。

### 6.1 改进：相同结果只算一次

记忆化是第一次算出F(k)后保存，后面直接取；自底向上则从F(0)、F(1)往上依次算。它们都只需处理线性数量的状态。

只求最终一项时，可以只保留前两项：

```text
procedure FIB_ITER(n)
    if n ≤ 1 then return(n) endif
    a ← 0; b ← 1
    for i ← 2 to n do
        c ← a+b
        a ← b
        b ← c
    repeat
    return(b)
end FIB_ITER
```

更新顺序不能写成先a←b再直接用a+b计算新项，否则会丢失旧a。这里用临时变量c保存新值。时间Θ(n)，辅助空间Θ(1)。这为后面理解动态规划作准备。

## 7. 课件例3.3：恰好装满的递归

课件第6页给定正整数质量和容量，要求选若干物品使质量和恰好等于容量。它没有物品价值，不是最大价值背包。

自编例子：重量[2,4,5]，目标6。可以选2和4，因此存在可行方案；目标8则无法恰好组成。

定义EXACT(i,c)：只使用前i件物品，能否挑出一个子集，使质量和恰好等于c。可以把c理解为“这一层还差多少重量”。它返回true或false，表示有方案或无方案，当前代码不直接返回物品清单。

对重量[2,4,5]，数组下标从1开始，所以w(1)=2、w(2)=4、w(3)=5。“前i件”说的是可用范围；本次从这个范围中最后一件w(i)开始决定，剩下再交给前i−1件。

```text
procedure EXACT(i,c)
    //global正整数数组w；i≥0，c≥0；返回是否存在方案//
    if c = 0 then return(true) endif
    if i = 0 then return(false) endif
    if w(i) > c then
        return(EXACT(i-1,c))
    endif
    return(EXACT(i-1,c) or EXACT(i-1,c-w(i)))
end EXACT
```

### 7.1 先把i和c翻译成人话

| 调用 | 还有哪些物品可用 | 还需要组成多少 | 它在问什么 |
|---|---|---:|---|
| EXACT(3,6) | 2、4、5 | 6 | 三件中能否选出和为6的子集？ |
| EXACT(2,6) | 2、4 | 6 | 不用5，只靠2和4能否凑6？ |
| EXACT(2,1) | 2、4 | 1 | 已经选了5，剩下能否再凑1？ |
| EXACT(1,2) | 2 | 2 | 只剩重量2的物品，能否凑2？ |
| EXACT(0,2) | 没有 | 2 | 没东西可选但还差2，失败 |
| EXACT(0,0) | 没有 | 0 | 已经凑够，不需再选，成功 |

i不是“已经选了几件”，而是“可用的前缀有几件”。c不是“已经选了多重”，而是“这一层还需要多少”。每次调用都有自己的i和c，传入i−1、c−w(i)不会把父调用的i、c直接改掉。

### 7.2 为什么只有选与不选两种情况

开始调用EXACT(3,6)，这一层处理第3件，其重量w(3)=5。

如果不选5，目标仍是6，但物品只剩前两件2和4，因此新问题是EXACT(2,6)。如果选5，目标已经完成其中5，还差6−5=1，且5不能重复选，因此新问题是EXACT(2,1)。

一般写成：

```text
不选第i件：EXACT(i−1,c)
选第i件：  EXACT(i−1,c−w(i))
```

两条分支的i都减1，因为无论选不选，第i件都已经决定完了。只有选分支扣减c。若选分支仍使用i，就可能把同一件反复使用，改变了原题“每件最多选一次”的含义。

所有合法方案中，第i件一定要么不在方案里，要么在方案里，两个分支覆盖全部可能。只要任意一种能成功，就存在解，所以用or连接。

### 7.3 按顺序读每个出口

`if c=0 then return(true)`：还差0，表示目标已经凑够。把后面物品全不选就可以，因此立即成功；并不要求所有物品都必须用完。

`if i=0 then return(false)`：这条执行到时，前面的c=0已经被排除，所以含义是“还有重量要凑，但已经没有可用物品”，只能失败。

EXACT(0,0)必须返回true，空集合的质量和就是0。所以在这一写法中，先检查c=0，再检查i=0；不能不分情况地先把所有i=0都判成失败。

`if w(i)>c then return(EXACT(i−1,c))`：例如还差3却遇到重量5的物品。质量都是正数，选5后只会超过目标，无法靠再选正数减回来，所以这一件只能不选，目标c保持不变。

前两个出口还确保：只有i≥1时才访问w(i)，不会访问w(0)。跳过过重物品也确保选分支的c−w(i)不会为负。

### 7.4 return和or怎样配合

`return(EXACT(i−1,c))`表示：先调用更小的问题，拿到它返回的true/false，再把同一个结果交回上一层。本层跳过了一件物品，并不等于整道题已经失败。

or的规则为：

| 左边结果 | 右边结果 | 合起来是否有方案 |
|---|---|---|
| false | false | false |
| false | true | true |
| true | false | true |
| true | true | true |

本书还有短路规则：左边已经true时，or整体已确定为true，右边不用再调用。最后一行可以展开成下面更容易读的等价写法，前面的出口和过重检查保持不变：

```text
canSkip ← EXACT(i-1,c)
if canSkip then
    return(true)
endif
return(EXACT(i-1,c-w(i)))
```

这表示先试不选；不选已经成功就立即返回；不选失败后再试选。不是要求两条分支都成功。

### 7.5 EXACT(3,6)的完整实际调用树

上一版只概述成功路线，容易漏掉“先试失败分支，再换选择”的过程。按代码从左到右真正执行为：

```text
EXACT(3,6)：可用2、4、5，目标6
├─ 不选5 → EXACT(2,6)
│  ├─ 不选4 → EXACT(1,6)
│  │  ├─ 不选2 → EXACT(0,6) = false
│  │  └─ 选2   → EXACT(0,4) = false
│  │  所以EXACT(1,6) = false
│  └─ 选4 → EXACT(1,2)
│     ├─ 不选2 → EXACT(0,2) = false
│     └─ 选2   → EXACT(0,0) = true
│     所以EXACT(1,2) = true
│  所以EXACT(2,6) = false or true = true
└─ 选5 → EXACT(2,1)：左边已true，短路，不实际调用

最终EXACT(3,6)返回true。
```

逐层解释：只靠一件重量2无法凑6，因此先前的不选4分支失败；换成选4后，还差2，这次再选重量2恰好完成。实际成功方案是不选5、选4、选2，总重6。

找到一个方案已经足以回答“有没有”，因此原函数会短路，不负责继续枚举全部方案。true本身也没有携带选物品的清单；上面的清单是我们根据成功调用路径读出来的。

### 7.6 为什么目标8返回false

三件物品的所有子集为：

| 选取 | 总重量 |
|---|---:|
| 什么也不选 | 0 |
| 2 | 2 |
| 4 | 4 |
| 5 | 5 |
| 2和4 | 6 |
| 2和5 | 7 |
| 4和5 | 9 |
| 2、4、5 | 11 |

没有8，所以任何选择分支都无法成功，最终返回false。代码自动用递归探索这些选择，并通过过重检查等省去部分无用分支。

### 7.7 复杂度与考试表达

每件物品最多产生选、不选两个分支，最坏探索指数数量的选择，时间上界O(2ⁿ)。短路和过重检查能减少实际调用，但不能保证所有输入都很快。

每次i减1，最长同时存在的调用链为线性深度，所以辅助栈空间O(n)。总调用数很多，与同时占用的栈层数是不同概念。

答题顺序可写：定义状态EXACT(i,c)→c=0成功、i=0且c>0失败→过重只能不选→否则选/不选取逻辑或→说明i递减保证终止→分析时间与栈空间。很多(i,c)可能重复，后面DP章节会学习保存这些状态结果。

## 8. 考试怎样写递归设计题

先写清函数或过程的含义，例如“F(i,c)表示前i件能否组成c”；写合法输入与返回值；给出口；写分解关系；说明每次规模怎样减小；最后写时间与栈空间。

证明正确性时，可以用归纳思路：最小规模由出口直接正确；假设小规模结果正确，再说明本层组合能得到原问题正确答案。证明终止时另指出非负整数规模不断减少，最终到出口。

| 容易丢分的地方 | 检查方法 |
|---|---|
| 用答案大小当运行时间 | 单独写答案F(n)与耗时T(n) |
| 只写递推没有出口 | 看n=0或最小规模会怎样 |
| 递归参数不减小 | 证明每条调用链会靠近出口 |
| 递归返回值没被使用 | 看调用后怎样组合出本层结果 |
| 时间算了但漏空间 | 找最长调用链，不数整棵树当栈深 |
| 把所有递归说成低效 | 检查是否存在重复求解，及调用成本 |

## 10. 标准答案与详细解析

每题先列可直接核对的答案，再解释过程。若考题要求画树、写递推或分析复杂度，应把对应过程一并写出。

### 第1题：阶乘的值与调用次数

**答案：FACT(0)=1，FACT(3)=6。FACT(3)共执行4次FACT调用，含最初那次；由内部产生的递归调用为3次，实际乘法也为3次。**

向下调用为FACT(3)→FACT(2)→FACT(1)→FACT(0)。FACT(0)直接返回1，不做乘法；FACT(1)、FACT(2)、FACT(3)分别算1×1、2×1、3×2，得到1、2、6。

“调用次数”“递归调用次数”“乘法次数”可能采用不同计数口径，必须先看题目是否包括第一次调用。本题问总共调用，计入最初的FACT(3)，所以是4次。

### 第2题：递归不缩小与错误出口

**答案：改为FACT(n)时，n>0的调用无法结束；把正确出口的返回值改成0时，所有非负整数输入的最终结果都会是0。**

第一种错误以n=3为例：FACT(3)为了返回3×FACT(3)，又调用同样的FACT(3)，没有一次向0靠近。n=0仍会直接走出口，但正数输入无法完成，真实程序通常最后因栈资源不足报错。

第二种错误虽然仍会终止，但FACT(0)=0，向上依次变成FACT(1)=1×0=0、FACT(2)=2×0=0、FACT(3)=3×0=0。出口不仅要能终止，也必须给出正确的小规模答案。

### 第3题：四盘汉诺塔

**答案：最少移动15次。一般时间Θ(2ⁿ)，辅助调用栈空间Θ(n)。**

设M(n)为移动次数：M(0)=0，M(n)=2M(n−1)+1。两个M(n−1)分别对应先移开上层小盘、最后把小盘移到目标；中间的1为移动最大盘。

| 盘数n | 0 | 1 | 2 | 3 | 4 |
|---|---:|---:|---:|---:|---:|
| 移动次数 | 0 | 1 | 3 | 7 | 15 |

展开得M(n)=2ⁿ−1，代入4得到16−1=15。两侧递归先后执行，最长调用链的盘数从n降到0，栈深是线性，不是把整个递归树所有调用同时放进栈中。

### 第4题：FIB(4)的完整调用树

**答案：FIB(4)=3；重复状态包括FIB(2)、FIB(1)、FIB(0)。本例总调用9次，但同时存在的最深调用链只有4层；一般辅助栈空间Θ(n)。**

按本讲FIB(0)=0、FIB(1)=1的代码，完整关系如下。括号右侧标返回值：

```text
FIB(4) = 3
├─ FIB(3) = 2
│  ├─ FIB(2) = 1
│  │  ├─ FIB(1) = 1
│  │  └─ FIB(0) = 0
│  └─ FIB(1) = 1
└─ FIB(2) = 1
   ├─ FIB(1) = 1
   └─ FIB(0) = 0
```

从叶子向上相加：FIB(2)=1+0=1；FIB(3)=1+1=2；FIB(4)=2+1=3。FIB(2)出现2次，FIB(1)出现3次，FIB(0)出现2次；加上各1次的FIB(3)、FIB(4)，总共9次。

先算完左分支再算右分支，最长链如4→3→2→1。因此总工作量虽然指数增长，辅助栈空间仍为线性。一般时间为指数级，可写上界O(2ⁿ)，紧确阶为Θ(φⁿ)。

### 第5题：恰好装满与空集合

**答案：EXACT(3,6)=true，选重量2和4；EXACT(3,8)=false；EXACT(0,0)=true。**

三件物品的全部子集和为0、2、4、5、6、7、9、11。6对应2+4；列表中没有8，因此不能恰好组成8。这里要求恰好，不是总重不超过目标即可。

EXACT(0,0)的含义是没有可选物品、还需重量0，选择空集合就满足要求。因此这一版先判断c=0成功，再判断i=0失败。若不分情况先把i=0全判false，会把这个合法终点错判。

### 第6题：教材3.2（1）的数列通项

**答案：aₙ=n!，n≥0。**

已知aₙ=n·aₙ₋₁、a₀=1，逐层代入：

```text
aₙ = n·aₙ₋₁
   = n(n−1)·aₙ₋₂
   = n(n−1)(n−2)·aₙ₋₃
   = …
   = n(n−1)…1·a₀
   = n!
```

检验a₁=1、a₂=2、a₃=6。若别的题给a₀=b，则会得到b·n!，初值不能丢。此题求数列值，不能直接把n!当成实现该递推的程序运行次数。

### 第7题：教材3.5的直线分平面

**答案：R(n)=1+n(n+1)/2；递推为R(0)=1，R(n)=R(n−1)+n。**

没有直线时，整个平面是1块。加入第n条直线，它与原有n−1条线相交；由于任意两线相交且无三线共点，这n−1个交点彼此不同，把新线分成n段。

每一段穿过一个旧区域并把它分成两块，所以每段增加1块，共增加n块。于是从n递减到0展开：

```text
R(n)=R(n−1)+n
    =R(n−2)+(n−1)+n
    =R(0)+1+2+…+n
    =1+n(n+1)/2
```

代入n=1、2、3分别得到2、4、7块。题目要求解释时，应写出“n−1个不同交点→n段→新增n块”，不能只给最终公式。
